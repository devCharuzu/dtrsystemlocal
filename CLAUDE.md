## Running the app

```bash
# From the form48-dtr/ directory (where main.py lives)
source ../venv/bin/activate   # venv is one level up
uvicorn main:app --reload
```

Open `http://127.0.0.1:8000`.

## Architecture

This is a local-first FastAPI app (no auth, single-user) for Philippine government CSC Form 48 Daily Time Records.

**Core flow:**
1. HR uploads a biometric `attlog.dat` file → `services/dat_parser.py` parses it into `RawLog` rows, then resolves each employee's punches into `DTRCell` rows (slots: AM_IN, AM_OUT, PM_IN, PM_OUT).
2. HR views/edits the DTR grid (`/dtr/grid`) — edits are written via `POST /dtr/cell/update` and every change is recorded in `AuditLog`.
3. HR exports a PDF (`/dtr/pdf`) generated by `services/pdf_generator.py` using WeasyPrint and `templates/form48_pdf.html`.

**Alternate ingest:** HR can instead upload the biometric software's Excel report (`.xls`) at `/xlslogs/`. `services/xls_parser.py` reads the workbook's `Logs` sheet and feeds the punches through the *same* `_resolve_day_punches` / `_upsert_cell` functions the `.dat` path uses, so both sources produce identical `DTRCell` rows. The `.dat` pipeline is untouched by it.

**Key models** (`models.py`):
- `Employee` — employee directory; `employment_type` is `"PERMANENT"` or `"COS_JO"`
- `RawLog` — every raw biometric punch, preserved for audit
- `DTRCell` — final resolved time per slot per day; `is_flagged=True` means collision or schedule violation (displayed in red)
- `AuditLog` — tracks every HR edit to a `DTRCell`
- `Verifier` — certifying officer printed on the Form 48 PDF; one row can be `is_default=True`
- `UploadedDatFile` — prevents re-ingesting the same filename
- `UploadedXlsFile` — same guard for `.xls` imports, kept in its own table so the `.dat` history is unaffected

**Routers:**
- `routers/employees.py` — employee CRUD
- `routers/datlogs.py` — `.dat` file upload and ingest
- `routers/xlslogs.py` — `.xls` Excel report upload and ingest
- `routers/dtr.py` — DTR grid view, cell edits, verifier management, PDF export, audit log

**Dat parsing logic** (`services/dat_parser.py`):
- Collision rule: punches within 5 minutes in the same half-day → blank cell + `is_flagged`
- Slot assignment: prefers device punch-state codes (`0`=AM_IN, `2`=AM_OUT, `3`=PM_IN, `1`=PM_OUT); falls back to time-of-day sequence heuristics
- Schedule flags: AM_IN after 08:00, AM_OUT before 12:00, PM_IN after 13:00, PM_OUT before 17:00

**Xls parsing logic** (`services/xls_parser.py`, requires `xlrd`):
- Reads only the `Logs` sheet: month/year from the `2026/07/01 ~ 07/31` header, day columns from the `No. | Name | Department | 1 | 2 …` row, and each day cell's newline-separated `HH:MM` punches
- Employee linking: short name first (`ASantos` → `ALICE B. SANTOS`, via initial+surname / initials+surname / surname, ambiguous keys dropped), then the `No.` column as biometric number. Every link is reported in the upload result; unlinked rows are skipped, never guessed
- Lunch handling: employees scan **once** at lunch, and that punch is both the AM time-out and the PM time-in. The report prints it twice in the day cell, so the parser collapses the repeat (exact-duplicate times only) and then `_mirror_lunch_punch()` copies the resolved time into whichever noon slot the resolver left empty. Guards: only inside 11:00–14:00, never over a slot the collision rule blanked, and never when the 12-hour storage format would make the target slot misread the time (`AM_OUT` can't hold an afternoon time, `PM_IN` can't hold a morning one). `.dat` has second resolution and its own in/out state codes, so it is unaffected
- Resolution, collision flags, and schedule flags are the `.dat` rules, reused as-is. The Excel report carries no device punch-state codes, so the sequence heuristics always apply
- Self-check: `python test_xls_parser.py`

**Time storage:** times are stored as 12-hour strings without AM/PM suffix (e.g. `"8:05"`, `"12:30"`). `format_display_time()` in `models.py` converts them for display. `_is_schedule_flag()` in `routers/dtr.py` infers 24-hour context from the slot name.

**Database:** SQLite at `form48.db` (same directory as `main.py`). Schema is auto-created on startup via `Base.metadata.create_all`. For schema changes, add a migration script like `migrate_employement_type.py`.
